# Команда «Табеля»

Координатор Astra принимает поручение, назначает владельца, фиксирует критерии приёмки и границы изменений. Он разрешает пересечения между функциями, сверяет работу с требованиями, принимает результат тестировщика и проверяет публикацию полной и облегчённой сборок и ZIP для Яндекс Диска.

## Сборщик информации с почты — Luna

Проверяет оба согласованных ящика, архив и спам. Сверяет отдельные сообщения в цепочках с последней проверкой, различает новые требования, дополнения, повторы и образцы. В приватном каталоге фиксирует источник, контрольную сумму и назначение образца.

## Общие роли Sol

| Роль | Область ответственности |
|---|---|
| Дизайн и интерфейс | Проверяет доступность действий, навигацию, размеры окон, масштаб экрана и читаемость. |
| База данных | Отвечает за SQLite, миграции, резервные копии, согласованность данных и перенос между версиями. |
| Тестировщик | Независимо воспроизводит ошибку, проверяет реальные сценарии и обезличенные регрессии, указывает проверенную среду и ограничения. |
| Общие функции и настройки | Главное меню, справочники, архив, общие настройки, обновления, сборка и комплектация выпуска. |

## Передача работы

1. Для почтового поручения сборщик передаёт координатору новые сообщения и приватный перечень образцов. При запросе только сводки работа завершается отчётом.
2. Координатор открывает в журнале карточку с владельцем, целью и проверяемым результатом. Независимым ролям можно работать параллельно. За конкретное изменение файла отвечает один агент.
3. При запуске агент получает карточку, профильные инструкции, ссылки на коммиты и нужные образцы. Проверяет актуальную ветку. Существенное решение записывает кратко: наблюдение, принятое решение, основание, проверка и следующий шаг.
4. Тестировщик сообщает результат координатору. При расхождении фиксирует воспроизводимый пример и возвращает задачу владельцу. При изменении бизнес-правила координатор сверяет трактовку с пользователем.
5. После приёмки координатор организует одну итоговую сборку, проверяет артефакты и закрывает карточку. Если задача прервана, последняя запись описывает конкретное действие для продолжения.

Журнал содержит выводы и проверяемые основания ключевых решений. Исходные клиентские документы, частные письма, ссылки на закрытые материалы и персональные данные хранятся отдельно. Для публичных тестов используйте обезличенные примеры.

При регрессионной проверке документов найдите в личной библиотеке владельца архив `tabel-private-fixtures.zip`. Манифест внутри связывает примеры с письмами и содержит SHA-256. Проверяйте копии в отдельном каталоге вне Git. При пополнении набора сравнивайте хеши, сохраняя связь повторных вложений с письмами.
