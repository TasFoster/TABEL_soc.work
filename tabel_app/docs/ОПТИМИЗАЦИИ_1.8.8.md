# Оптимизации 1.8.8

## Обзор и выбранные изменения

Статически просмотрена структура 94 Python-файлов app (14 250 строк на начало
обзора), циклы с SQL, загрузкой файлов, нормализацией и копированием объектов.
Прицельно проверены общая БД, архив, табель, общие ODS-помощники, сервисы реестра,
проезда, услуг, госзадания и приложение к табелю. Это не доказательство отсутствия
всех возможных узких мест. Оптимизировались воспроизводимые лишние операции.
Сетевое обновление уже вынесено в поток. Календарные правила и финансовые расчёты
не изменялись. OCR и сторонние зависимости не переписывались без профиля реальной нагрузки.

1. **XLS табеля.** Подготовленные стили переиспользуются внутри одного вызова generate.
   Кеш не переживает генерацию, поэтому новый месяц получает свою заливку.
2. **Состав отделений.** Два запроса вместо одного запроса сотрудников на каждое
   отделение. Порядок, ID, пустые отделения, дробный оклад и нумерация сохранены.
3. **Показатели и отсутствия.** Пакетное чтение нужных ключей по 900 параметров.
   Исключены запросы/подключения по каждому сотруднику. Нет кеширования изменяемых данных.
4. **Последние параметры документа.** WHERE feature + ORDER BY + LIMIT 1 вместо
   чтения полного архива. Добавлен повторяемый индекс
   `idx_documents_feature_latest(feature, created_at DESC, id DESC)`.
   Содержание документов не загружается, порядок при одинаковой дате сохранён по id.
5. **ODS.** Одна повторяющаяся строка выделяется с сохранением сжатого префикса
   и хвоста. Миллион повторов не превращается в миллион объектов.

## Измерения

Команда `python tabel_app/tools/benchmark_optimizations.py`.
Синтетические данные, временная SQLite, медиана трёх запусков в Linux/Python 3.12.
Это измерения отдельных операций, не обещание ускорения всего приложения на ПК.

| Операция | До, мс | После, мс |
|---|---:|---:|
| XLS, 100 сотрудников | 761,80 | 59,00 |
| Загрузка 100 отделений / 2000 сотрудников | 8,70 | 3,23 |
| Последние параметры из 20 000 документов | 36,41 | 0,17 |
| Обращение к строке среди 2000 повторов ODS | 40,76 | 0,06 |

Запросов на чтение отделений стало 2 вместо 101. При обращении к одной строке
из 2000 повторов создаётся 3 физических строки вместо 2000.

## Проверки

- 31 unit-тест, включая пакет из 1001 ключа, порядок записей и восстановление индекса
  на заполненной базе без изменения документов.
- Значения, XF-оформление и объединения XLS совпали до/после на 1, 30, 100 сотрудниках.
- Самопроверки main.py для табеля, приложения и проезда прошли в изолированном каталоге.
- Логические строки, значения, формулы и ссылки на стили ODS проезда совпали до/после.
- ODS-повторы проверены на начале, середине, конце, вложенных группах и миллионе строк.
- Все модули компилируются. Windows-сборка дополнительно запускает unit-тесты и
  frozen smoke-тесты полной и облегчённой версий.

Установка поверх рабочей версии на компьютере пользователя и весь ручной GUI-сценарий
в этой среде не проверялись. Рабочие базы и документы пользователя не изменялись.
