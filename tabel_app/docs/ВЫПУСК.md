# Сборка, выпуск и обновления

## GitHub Releases

Основной канал обновления — публичный репозиторий `TasFoster/TABEL_soc.work`.
Программа читает `https://github.com/TasFoster/TABEL_soc.work/releases/latest/download/version.json`.
Манифест содержит записи `full` и `lite` для Windows, `linux-amd64-full` и
`linux-amd64-lite` для Ubuntu. В каждой записи указаны ссылка на файл конкретного
тега, размер и SHA-256. Для загрузки нужен доступ к публичным GitHub Releases
или к зеркалу на Яндекс.Диске.

Проверка запускается в фоне при открытии программы и по кнопке. В установленной
Windows-версии «Обновить сейчас» запускает Inno Setup и закрывает приложение.
Портативная Windows-копия скачивает установщик в папку «Загрузки». В Ubuntu
программа сохраняет проверенный пакет `.deb` в выбранный каталог. Для обновления
закройте «Табель» и установите скачанный пакет через менеджер пакетов или `apt`.

## Установка на Ubuntu

Поддерживаемые системы — Ubuntu 22.04 LTS и 24.04 LTS, архитектура amd64.
Скачайте `tabel_<версия>_amd64.deb` для полной или `tabel-lite_<версия>_amd64.deb`
для лёгкой версии. Откройте пакет в менеджере пакетов или запустите из каталога
загрузки команду `sudo apt install ./имя-пакета.deb`, подставив имя файла.
После установки в меню приложений появится «Табель (полная версия)» или
«Табель (лёгкая версия)». Команды запуска — `tabel` и `tabel-lite`.

При обычной установке `apt` загрузит зависимости из репозиториев Ubuntu.
В полной сборке распознавание билетов использует Tesseract с русским и английским
языками. LibreOffice Writer и Calc рекомендуются для просмотра результатов
и проверки страниц при обработке актов.

Пользовательская база, справочники, архив и настройки находятся в каталогах
`~/.local/share/tabel/data` и `~/.local/share/tabel-lite/data`. При заданном
абсолютном `XDG_DATA_HOME` вместо `~/.local/share` используется этот каталог.
Версии можно установить одновременно. Установщик обновляет файлы пакета и
сохраняет пользовательские данные. Для переноса базы с Windows используйте
«Перенос данных» в главном меню.

## Как выпустить новую версию

1. Внести проверенные изменения в `main`.
2. Обновить `tabel_app/RELEASE_NOTES.md` и увеличить `tabel_app/VERSION`.
3. Отправить изменения одним коммитом. Изменение VERSION запускает workflow
   **Windows and Ubuntu installers**.
4. В Actions проверить тесты и обе Windows-сборки, затем обе Ubuntu-сборки и
   проверки установки, запуска и обновления в Ubuntu 22.04 и 24.04.
5. Workflow формирует общий манифест и публикует релиз `v<версия>`. До загрузки
   всех файлов релиз остаётся черновиком.

`version.json` создаётся из готовых установщиков, вручную его редактировать не нужно.
Один VERSION используется в установщиках, программе и манифесте.
Windows-установщики называются `Tabel-full-setup.exe` и `Tabel-lite-setup.exe`.
Повторная публикация требует увеличить VERSION. После ошибки повторный запуск
допускается для черновика с тем же commit SHA.

Ручной запуск выполняется через GitHub Actions, **Windows and Ubuntu installers**,
**Run workflow**, ветка **main**. Для публикации используется автоматический
`GITHUB_TOKEN` с разрешением `contents: write`.

## Переход с Яндекс.Диска

Версии до этого выпуска знают только Яндекс.Диск. Для перехода:

- либо вручную установить новый установщик поверх существующей установки;
- либо разместить новый `version.json` и оба установщика в прежней публичной папке
  Яндекс.Диска. Старый updater поддерживает поле `url` и скачает установщик с GitHub.

Новые версии проверяют GitHub и Яндекс.Диск и выбирают самую новую доступную
версию для своей платформы и варианта. Чтобы обновить зеркало, распакуйте содержимое
`Tabel-Yandex.zip` в публичную папку. Архив содержит общий манифест и все четыре
установщика.

## Локальная Windows-сборка

Python 3.11 x64, Inno Setup 6, PowerShell и GitHub CLI (для публикации).

```powershell
python -m pip install -r tabel_app/requirements-build.txt
powershell -ExecutionPolicy Bypass -File tabel_app/tools/build_release.ps1 -OutDir C:\tabel-release
```

Новый генератор: `tools/make_manifest.py`. Прежний `tools/make_manifest.ps1` предназначен
для старой ручной упаковки Яндекс.Диска; в GitHub workflow он не используется.
Сборочные скрипты PowerShell остаются ASCII-only, `.iss` сохраняются в UTF-8 с BOM.

## Локальная сборка пакетов Ubuntu

На Ubuntu 22.04 amd64 с Python 3.11 и рабочим Tkinter:

```sh
python -m pip install -r tabel_app/requirements-build.txt
tabel_app/tools/build_deb.sh /tmp/tabel-release
```

Проверка через `tabel_app/tools/smoke_deb.sh /tmp/tabel-release` устанавливает
и обновляет пакеты через `sudo apt-get`. Запускайте её в одноразовой Ubuntu с
`xvfb`, `xauth` и `desktop-file-utils`. Проверка использует отдельные
пользовательские каталоги и сверяет запись SQLite и файл настроек после обновления.

## Проверки без Windows

```sh
python -m unittest discover -s tabel_app/tests -v
```

Эти тесты проверяют выбор варианта, ссылки манифеста, размеры, хеши, отказ при неверном
хеше и сохранение локального тестового источника. Они не заменяют запуск Windows EXE,
проверку распознавания реальных билетов и установку поверх существующей версии.
